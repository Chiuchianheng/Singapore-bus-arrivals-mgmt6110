## 2. My findings

### Finding 1
- Where: [https://singapore-bus-arrivals-mgmt6110.vercel.app](https://singapore-bus-arrivals-mgmt6110.vercel.app), home page, the stop
  code box next to the Load button
- What I did, what I saw: I typed a stop name, Orchard, and pressed Load. A
  message said "Please match the requested format." and nothing loaded. A
  visitor who does not know the 5-digit code has no way to find or choose a
  stop.
- Which heuristic: 6, Recognition Rather than Recall
- Screen or system: System. The page only sends a stop code and gets back the
  arrivals for that one stop. To let a visitor find a stop by name, it would
  first need a list of stops with their names, which it is never sent.
- Severity, and why: 4, driven by how often it happens. Most visitors will not
  know the 5-digit code. Newcomers, tourists and residents in an unfamiliar
  area do not know it, and even regular riders who check from home before they
  leave cannot read it on the sign at the stop. For all of them the product
  cannot do its one job, and looking the code up in another app takes long
  enough that the bus may have left.
- The repair: A visitor who does not know the stop code can find their stop by
  its stop name or its road name, sees the code, stop name and road together
  for each stop found, so that stops with similar names can be told apart,
  and chooses one without typing the full code.

### Finding 2
- Where: https://singapore-bus-arrivals-mgmt6110.vercel.app, home page, the
  search area at the top
- What I did, what I saw: I looked on the home page for a way to find the bus
  stops near where I am. I saw only the stop code box, the Load button and the
  Add to my stops button. There is nothing that shows the stops near me or
  near a place I name.
- Which heuristic: 7, Flexibility and Efficiency of Use
- Screen or system: System. The page only receives the buses and their arrival
  times for the one stop code it sends. To show the stops nearest to a
  visitor, it would first need the location of every stop, which it is never
  sent.
- Severity, and why: 3, driven by how often it happens. Without a way to find
  nearby stops, any visitor in an unfamiliar area meets this problem, and it
  catches them again every time they go somewhere new.
- The repair: A visitor who knows neither the code nor the name of their stop
  can see the stops nearest to where they are, or to a place they name, tell
  which one is closest, and see which buses they can take from it.

### Finding 3
- Where: https://singapore-bus-arrivals-mgmt6110.vercel.app, the top of the
  page, the Status check button beside Refresh
- What I did, what I saw: I pressed Status check. The page showed technical
  text: {"checkedAt": "...", "keyConfigured": true, "upstreamStatus": 200,
  "upstreamOk": true}. This button is for me to check the API, not for
  visitors.
- Which heuristic: 8, Aesthetic and Minimalist Design
- Screen or system: Screen. Removing the button from what visitors see needs
  nothing new from the system.
- Severity, and why: 2, driven by whether it damages the product's standing. A
  visitor may press it out of curiosity and think the site is broken when they
  see technical text.
- The repair: Visitors no longer see the internal status check on the page,
  while the builder can still check the system at /api/health.

### Finding 4
- Where: https://singapore-bus-arrivals-mgmt6110.vercel.app, Saved stops, the
  ✕ beside each saved stop
- What I did, what I saw: In Saved stops, I pressed the ✕ beside Stop 04121.
  The stop disappeared at once, with no question asking if I was sure, and
  there was no way to undo it. The only way back was to add the stop again.
- Which heuristic: 5, Error Prevention
- Screen or system: Screen. Asking before removing a stop needs nothing new
  from the system.
- Severity, and why: 2, driven by what it costs. A stop removed by mistake can
  be added again, but only if the visitor remembers or looks up its code.
- The repair: A visitor cannot lose a saved stop from a single accidental tap.

### Finding 5
- Where: https://singapore-bus-arrivals-mgmt6110.vercel.app, home page, the
  stop code box and the results below it
- What I did, what I saw: In a fresh private window, I loaded stop 11149, then
  loaded another stop, then tried to go back to 11149. The page keeps no list
  of the stops I searched recently. The address in the address bar stayed the
  same when I loaded the second stop. Pressing the browser's Back button did
  not return me to 11149. It left the site and went back to the page I was on
  before I opened it, so the only way back to 11149 was to type it again.
- Which heuristic: 3, User Control and Freedom
- Screen or system: Screen. The page already knows every stop code it has
  loaded, so it can keep a list of recent searches with nothing new from the
  system.
- Severity, and why: 2, driven by what it costs. The visitor can still get
  back by typing the code again or using Saved stops, but has to remember or
  look up the code again.
- The repair: A visitor can see the stops they searched recently and return
  to one of them without typing its code again.
  
### Finding 6
- Where: https://singapore-bus-arrivals-mgmt6110.vercel.app, home page, the
  results area where the incoming buses normally appear, after typing 99999
  and pressing Load
- What I did, what I saw: I typed 99999, a code for a stop that does not
  exist, and pressed Load. The page said "No buses are running from this stop
  right now." In the Network panel, the response was
  {stopCode: "99999", services: []}, with nothing to say the stop does not
  exist.
- Which heuristic: 9, Help Users Recognize, Diagnose, and Recover from Errors
- Screen or system: System. The response for a stop that does not exist is an
  empty list, which does not tell the page whether the stop exists, so the
  page cannot tell a wrong code from a stop with no buses.
- Severity, and why: 3, driven by what it costs. A visitor who mistyped the
  code may believe there is simply no bus right now, and wait or miss their
  bus instead of correcting the code.
- The repair: A stop code that does not exist is reported as such, and the
  visitor is told to check the code and try again.

## 3. My predictions
1. The three findings I expect my groupmates to raise, and the severity I
   expect them to give each:
   - Finding 1, at severity 4. It is easy to see because checking a bus is the
     first thing anyone does on the product, and a groupmate who does not know
     a stop code cannot use it at all.
   - Finding 2, at severity 3. It is easy to see because a groupmate who does
     not know a code will look for another way to find a stop, and the fastest
     way in an unfamiliar place would be the stops nearest to them, which the
     page does not offer.
   - Finding 4, at severity 2. It is easy to see because a groupmate who tries
     Add to my stops and then removes a stop finds it gone at once, with no
     way back.
2. The heuristic I think my product breaks worst: 6, Recognition Rather than
   Recall. The product exists for one job, checking when a bus will arrive,
   and it can only start when the visitor already remembers a 5-digit code.
   Without an easy way to find a stop, few people will want to use it.
3. The finding that would show my own evaluation was wrong: If a groupmate
   raises a finding of severity 3 or higher under heuristic 1, Visibility of
   System Status, such as not noticing that the bus times are updating after
   pressing Refresh, where only the small arrow on the button turns, my
   evaluation was wrong. I judged that the turning arrow and the "Checking the
   road…" message were enough, and I tested the waits only on my own devices,
   already knowing where to look.
